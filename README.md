# 演示机盘点与系统还原平台

门店演示机全流程管理：门店/展台/设备登记、开闭店盘点、顾客试用异常登记、系统还原与版本校验、调店交接、退仓复核。设备、账号与数据均为样例。

## 一条本地启动命令

```bash
./run.sh
# 或
python3 -m app.server --reset
```

`--reset` 会清空重建 SQLite 并生成 **离线、错位、调店** 三类样例。启动后访问 <http://127.0.0.1:8000>。

仅生成样例不启动服务：

```bash
python3 -m app.seed --reset
```

无需任何第三方依赖，Python 3.10+ 标准库即可运行。

## 核心业务规则

- **开店盘点**：逐台确认实际位置、电量、外观、联网状态
- **闭店盘点**：核对序列号、充电底座与防盗线配件；少机须店长填说明才能关单
- **待还原**：设置变更或发现异常内容 → 设备进入 `pending_restore`；还原后必须 **演示账号、应用、壁纸** 逐字段校验通过，才回到"可展示"
- **调店**：申请即冻结原展位；店长批准生成交接记录（含底座/防盗线配件）；目标店店长可接收或拒收（拒收退回原展位、解冻并登记"调店拒收"异常）
- **退仓**：门店申请并保留证据，店长复核通过后设备退仓、展位解冻，证据文件持续保留
- **序列号唯一**：序列号为主键，且数据库唯一索引保证同一展台同时只有一台未退仓设备——同一序列号不可能同时属于两个展位
- **并发安全**：盘点条目带 `version` 乐观锁，后提交且基于旧版本的请求返回 409 与当前记录，防止覆盖

### 异常处理对照

| 异常 | 处理 |
|---|---|
| 设备离线 | 盘点标记离线；离线时还原下发失败，保持待还原并自动重试 |
| 防盗线报警 | 导购上报；可在设备/展台弹窗复核 |
| 外观划伤 | 登记异常并可写本地证据文件 |
| 账号登出 | 盘点联动异常；还原后自动闭环 |
| 还原失败 | 保持待还原，进程内调度器自动重试（默认最多 3 次），可点"模拟失败"演示 |
| 展位错放 | 实际展位 ≠ 登记展位即标记 |
| 闭店少机 | 登记 `closing_missing`，店长说明后才能关单 |
| 调店拒收 | 退回原展位解冻，登记拒收异常 |

## 界面

- 配色：**展示白 / 曜石黑 / 品牌中性蓝**
- **展台平面图**：SVG 严格按柜面坐标排布，设备缩略图统一 9:19.5 比例，冻结展位虚线显示
- **盘点模式**：左侧逐台聚焦列表 + 中部单台大卡片 + **固定底部操作条**（进度、上一台/保存并下一台/关单）
- **还原页**：期望配置与实际配置并排，差异项按字段（账号版本/壁纸/应用/设置）逐行高亮，应用缺失/多出分别标注

## 进程内任务

`app/scheduler.py` 起一个守护线程（30 秒一拍）：

- 到开店/闭店时间且对应盘点单未关闭 → 顶栏铃铛出现提醒
- 存在 `failed` 且未超最大次数的还原任务 → 自动重试并提醒结果

## 本地存储

```
data/
├── demo.db                # SQLite：设备/展台/盘点/异常/还原/调店/退仓全部状态
├── evidence/              # 外观证据（文本/图片原样保存，退仓后仍保留）
└── packages/              # 离线还原配置包（按机型生成 JSON）
```

## 目录结构

```
app/
├── db.py          # SQLite schema 与连接
├── errors.py      # 领域错误（403/409/412…）
├── adapters.py    # 模拟 MDM 设备管理适配器 + 防盗充电底座适配器
├── services.py    # 领域服务与 RBAC
├── scheduler.py   # 进程内提醒 / 失败重试
├── seed.py        # 演示样例（离线/错位/调店）
├── server.py      # 标准库 HTTP + JSON API + 静态文件
└── static/        # 单页前端（index.html / styles.css / app.js）
tests/             # 领域测试 + HTTP 集成测试
run.sh             # 一条本地启动命令
```
